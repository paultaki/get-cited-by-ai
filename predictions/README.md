# Registered predictions

One file per prediction, committed BEFORE the outcome data exists. The first
commit date is the receipt that the bet came before the result. That only works
if the files never get reworked, so the rule is append and score only: after
registration, the only edits a file takes are its scored outcome and dated
notes. No band loosening, no rewording, no style cleanup. If a file reads
rough, that is what frozen looks like.

Deleting and re-registering a file would reset its timestamp to after the
intervention it describes, which is the exact failure this folder exists to
prevent. It does not happen here, including for cosmetic reasons.

Open predictions carry their score-by dates in each file's table. Scored files
keep the outcome next to the original band, so hits and misses stay equally
visible.
